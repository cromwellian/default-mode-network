# DX Audit — clone → first artifact (2026-06-10)

Goal: a non/semi-technical, terminal-comfortable person (possibly AI-assisted) clones the repo,
builds a taste profile, and generates artifacts — without hitting a wall.

Method: fresh clone in `/tmp`, README quick start followed verbatim on macOS (Intel), plus a
4-agent code sweep (prepare/import path, wander path, output/agent path, docs drift).
Findings marked **[verified]** were reproduced live; **[code-read]** were found by reading
code and still need a repro during the fix.

## Where the experience actually breaks (P0)

1. **`uv sync` fails on Intel Macs — quick start dies at step 2.** [verified]
   `sentence-transformers` is a *core* dependency (pyproject.toml:18) and the lockfile pins
   `torch 2.12.0`, which has no Intel-mac wheel. Ironically the README brags about a
   hash-embedding fallback when sentence-transformers is missing — a fallback that can never
   trigger because install fails first. Proof: even this machine's working venv has
   *neither torch nor sentence-transformers* (the profile was built on fallback embeddings
   all along, installed before the pin tightened).
   **Fix:** move `sentence-transformers` to an `embeddings` extra, relock. Verified locally:
   sync goes from *broken* to **5 seconds**, and the whole pipeline runs fine on fallback.
   *(Fixed in PR #10, which also stamps profiles with their embedding backend and refuses
   to wander on a mismatch, so an ST-built profile can't silently score hash vectors.)*

2. **No API key → the system silently produces garbage.** [verified]
   With no key set, `prepare.py --interactive` runs a *real* interview, then silently labels
   clusters with the stub LLM ("sourdough & baking"); `explore.py` runs a full wander writing
   templated stub briefs. The only tell is one dim line ("LLM provider: stub") that means
   nothing to a newcomer. A real run can waste 12 minutes producing fake output with zero
   warning (dmn/llm.py:196-228 falls through to stub on any init failure).
   **Fix:** loud red banner + confirm prompt when stub is selected outside `--dry-run`;
   validate the key with one cheap call at startup so a bad key fails in seconds, not mid-run.

3. **The README never tells you how to get from dry-run to real.** [verified]
   All entry points `load_dotenv()`, and `.env.example` exists — but the quick start never says
   `cp .env.example .env` or where to get an `ANTHROPIC_API_KEY`, what it costs per run, or
   what success looks like. `.env.example` is framed for Modal deployment, not first run.
   (Symptom: this repo's own checkout has no `.env`.)
   **Fix:** "Get a key" + cost-expectations section; reframe `.env.example` around the core path.

4. **README is a changelog wearing a README costume.** [verified]
   447 lines; the quick start starts at line 101, *after* "How labels are made", "Clustering
   (v0.4)", "Wander controls (v0.5)" — version-numbered sections that are meaningless noise to
   a first-time reader. Migration guidance for dev versions (v0.1.x) sits above "How it works".
   **Fix:** rewrite top of README as a ~60-line newcomer path (install → key → profile →
   wander → open journal); move changelog/deep-dives to `docs/`.

5. **Quick-start profile is degenerate: 100% noise.** [verified]
   `prepare.py --dry-run` puts all 12 synthetic interests in HDBSCAN's noise bucket
   ("Noise points: 12 (100.0%)", one `is_noise` cluster). Seed sampling skips noise, so the
   first wander falls back to `cold` seeds — the newcomer never sees taste-driven wandering
   work, on the exact path the README says proves the system works. Also: prepare --dry-run
   took **46 silent seconds** (needs a spinner and a look at where the time goes).
   **Fix:** synthetic seed profile should produce ≥2 real clusters (lower min_cluster_size for
   tiny N or fall back to kmeans); add progress feedback.

## Major friction (P1)

6. **Interview UX.** [verified] No progress indicator (6 questions, no "2/6"), no echo of what
   each answer captured, single-char answers silently dropped (manual.py:34-37), and after a
   *real* interview the success message says `Next: uv run explore.py --dry-run` — sending the
   user to stub output.
7. **Re-running prepare silently replaces the existing profile.** [verified] The dry-run
   profile (12 interests) vanished after `--interactive` with no "replacing N existing
   interests" warning. With real data that's scary.
8. **Deprecation warning on every iteration.** [verified] `duckduckgo_search` renamed → a
   RuntimeWarning prints mid-run, twice per wander, looking like breakage (dmn/tools/websearch.py:17).
   Fix: depend on `ddgs` or suppress.
9. **Invalid key / wrong provider fails late, not fast.** [code-read] Anthropic/OpenAI clients
   are constructed without validation; an invalid key surfaces minutes into the first synthesis
   call. Ollama health-check hint goes to stderr while the run continues on stub.
10. **No cost transparency.** [code-read] Nothing estimates LLM calls or $ before a 12-minute
    run. Even a static "~12–20 LLM calls, roughly $0.30–0.80 with Claude" line at startup
    would do.
11. **Ctrl-C safety.** [code-read] No signal handling around the loop; interrupting mid-write
    risks an unclean SQLite state, and users *will* Ctrl-C during the silent stretches.
12. **wander.py ends without showing the goods.** [code-read] explore.py prints top-3 briefs;
    wander.py just says "complete" — user has to go digging.
13. **Stale hardcoded model.** [verified] `claude-sonnet-4-5-20250929` (dmn/llm.py:84), one
    generation behind. Fix: bump, keep env-overridable, and catch model-not-found with a
    friendly "set DMN_LLM_MODEL=…" hint.
14. **Flag sprawl with no guided path.** [verified] explore.py ~13 flags, wander.py ~28
    interacting tuning knobs; README examples casually use 8 of them. Newcomers need exactly
    one command. (Fix is the wizard, #A below, not deleting flags.)

    "No browsers detected" with no "close Chrome and retry" hint. [code-read]
17. Takeout import: no explanation anywhere of what Google Takeout is or how to get one;
    empty/wrong dir silently yields zero items. [code-read]
18. `--execute --no-execute` and `--execute --sandbox none` resolve silently instead of
    erroring. [code-read]

20. `.env.example` gaps: `STABILITY_API_KEY`, `SUNO_API_KEY`, `GEMINI_API_KEY` read by code
    but absent; `HF_TOKEN` listed twice. [code-read]

    actually named `code` / `ml` / `activities`. [verified]
22. Four migration scripts exist, two documented, no guidance on when each applies. [verified]
23. Stub-LLM briefs aren't labeled as demo output in the journal HTML (a newcomer browsing
    `journal/index.html` can't tell demo from real). [code-read]
24. `eval.py rate <id>` — ID discovery (`eval.py unrated`) undocumented in program.md. [verified]
25. program.md/agent path: accurate overall (verified — flags match), but should point users
    at `journal/index.html`/`dashboard.html` at the end of a wander.

Disproved during verification (agents reported, live run contradicts): "explore.py points to
nonexistent journal/today.html" — the HTML builder does write `today.html`.

## What works well (keep)

uv-based single-command install (once unbroken), `--dry-run` end-to-end with zero keys,
graceful-degrade architecture, 77 fast tests, program.md agent path is accurate, every run
prints its journal paths, prepare prints the next command to run.

## Proposed improvement plan (maps 1:1 to issues)

- **A. `dmn setup` first-run wizard** — one command after clone: pick provider
  (paste Anthropic key / local model / demo mode), write `.env`, validate the choice with one
  cheap call, run the interview or import, build profile, print the exact next command.
  The local path doesn't just *detect* Ollama — it guides the install end-to-end the way a
  good pairing session would: detect hardware (Apple silicon vs Intel, RAM), recommend a
  model size that will actually be usable (8B on ≥16GB Apple silicon, 3B on 8GB, "use cloud,
  your machine will crawl" on Intel CPU), walk through `brew install ollama` + `ollama pull`,
  health-check the server, and explain the quality/speed/privacy trade-off it just made.
  Closes #2, #3, #6, #14 for the newcomer path.
- **B. Unbreak install** — `sentence-transformers` → `embeddings` extra, relock, note fallback
  behavior at prepare time ("using fast fallback embeddings; `uv sync --extra embeddings` for
  better clusters"). Closes #1.
- **C. Fail fast, loudly** — provider banner incl. model + est. cost; key validation at
  startup; red stub warning + confirm; Ctrl-C handler; model-not-found hint. Closes #2, #9,
  #10, #11, #13.
- **D. README rewrite + docs/ split** — newcomer path up top incl. "get a key", "local vs
  cloud" decision table, cost expectations; changelog and tuning guides move to docs/.
  Closes #3, #4, #17, #19–22.
- **E. First-wander output polish** — fix dry-run noise clustering; wander top-3 printout;
  ddgs warning; demo-output labeling in journal; eval.py discoverability. Closes #5, #8, #12,
  #23, #24, #25.
- **F. Input-path hardening** — interview feedback + progress; profile-replace warning;
  unknown-importer errors; browser-locked hint; Takeout how-to; flag-conflict errors.
  Closes #6, #7, #15–18.
- **G. End-to-end re-verification** — fresh clone on a clean machine profile, full real-key
  run, agent-path run via program.md, Modal smoke test (credits available). Gate for closing
  the project.
